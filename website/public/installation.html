Installation howto

Install native XiriBSD first. Then run xiriprep on the installed system to prepare an IRIX desktop from your own donor image.

Before you start

You can complete the native installation with just the ISO and a blank disk. The installer provides NetBSD, the Xiri compatibility module, native tools, and donor profiles; the first login opens native ctwm. All original IRIX executables, libraries, fonts, and desktop artwork come from your donor disk when you later run xiriprep.

  • Prismatic or IRIS, configured as an Indy with an R4400 or R5000 CPU, 256 MiB of RAM, and Newport graphics.
  • The installer xiribsd-indy-donor-profiles-11.99.11.iso, found under .work/images/ in the Xiri checkout for the documented build.
  • A new, blank 6144 MiB raw disk for XiriBSD. The installer will format this disk.
  • For the optional IRIX desktop, a standalone CHD or raw whole-disk image matching a supported donor profile. The reference releases are 6.5.22f and 6.5.30f; the current installer also recognizes the independently distributed SuperIRIX Indy 6.5.22m.

Prismatic is built on the IRIS emulator core. Choose either Prismatic’s settings menus or vanilla IRIS’s standalone window and TOML configuration, then follow the same guest installation and donor-import steps.

The same native installer includes all five desktop profiles below. Each installed system uses one donor release; keep separate system disks for 6.5.22f, 6.5.22m, and 6.5.30f.

Already installed an earlier XiriBSD Indy ISO, including xiribsd-indy-native-11.99.11.iso or xiribsd-indy-xiriprep-11.99.11.iso? Keep your disk and follow the tools-CD route for the current profiles.

Set up Prismatic

Start Prismatic and pause the machine. Open F9 and set the following options:

LocationSettings
GeneralIndy; R4400 or R5000; 256 MiB RAM; default Newport graphics; Graphics console; PROM boot: Keep existing.
Media: SCSI ID 1Choose New disk…, select Raw, enter 6144 MiB, and choose a new filename such as xiribsd-indy.raw. Select Create disk and attach to draft.
Media: SCSI ID 6Attach xiribsd-indy-donor-profiles-11.99.11.iso as the CD-ROM.

Save with F9, start with Ctrl + P, and continue to Install XiriBSD.

Set up standalone IRIS

You can run the iris executable directly, with its own graphics window and terminal monitor. The examples below use the current configuration documented in the Xiri project’s IRIS integration branch. This is the standalone emulator; Prismatic is optional. Upstream IRIS releases may contain a different set of NetBSD fixes.

Build the emulator

On a Linux workstation, install Git, Rust through rustup, and the host C/C++ build tools. The checkout’s rust-toolchain.toml selects nightly Rust automatically. See IRIS’s build and feature reference for host-specific options.

On your workstation, in a directory for source checkouts:

git clone --branch xiri https://github.com/salvogendut/iris.git iris
cd iris
cargo build --release --locked --bin iris

If you already have the matching IRIS checkout, build from there. The executable is target/release/iris. In the launch commands below, replace /absolute/path/to/iris with that checkout’s location. Older executables may reject the current [[devices]] syntax; rebuild from the current integration branch before using this example.

Create a separate Indy directory

Keep this machine’s configuration, disk, and NVRAM together. Create the blank 6 GiB disk once; this command refuses to overwrite an existing file.

On your workstation, in a directory for virtual machines:

mkdir xiribsd-indy
cd xiribsd-indy
python3 -c 'with open("xiribsd-indy.raw", "xb") as disk: disk.truncate(6144 * 1024 * 1024)'

Save the following as iris.toml in this new directory. Replace the installer path with the absolute path to your ISO. Use r5000 instead of r4400 for the 6.5.30f donor route.

prom = "(embedded)"
nvram = "nvram.bin"
banks = [128, 128, 0, 0]
headless = false
no_audio = true
scsi_deferred_int = true

[machine]
profile = "indy_ip24"
cpu = "r4400"

[graphics]
board = "newport"

[[devices]]
type = "hdd"
at = "scsi0/t1"
path = "xiribsd-indy.raw"
overlay = false

[[devices]]
type = "cdrom"
at = "scsi0/t6"
path = "/absolute/path/to/xiribsd-indy-donor-profiles-11.99.11.iso"

The default build includes the Indy PROM. The disk receives writes directly because overlay = false. Keep deferred SCSI interrupts enabled for NetBSD. Relative paths resolve from the directory where you launch IRIS, so always run this machine from xiribsd-indy.

On your workstation, from the new Indy directory:

/absolute/path/to/iris/target/release/iris --validate --config iris.toml
/absolute/path/to/iris/target/release/iris --config iris.toml

Proceed when validation reports ok. Stop any other emulator using the default monitor and serial ports first. Keep the terminal open alongside the guest window, and continue to Install XiriBSD. Right Ctrl releases the mouse from the guest.

Change CDs in standalone IRIS

After unmounting a CD inside the guest, press Right Ctrl + F12 in the IRIS window to select another ISO. With this single-disc configuration, the selection replaces the current disc. Use this for the tools CD or the donor data CD below.

To eject the single disc without replacing it, enter scsi eject 6 at the IRIS monitor in the host terminal. The monitor is separate from both the guest shell and the PROM. To start with an empty tray next time, stop IRIS after halting the guest and remove the path line from the CD-ROM entry, leaving its type and at lines.

Install XiriBSD

These guest steps apply to both frontends, with the new disk at SCSI ID 1 and installer CD at ID 6.

Boot the CD

Click the guest display, press Esc during startup, and choose 5 — Enter Command Monitor. If the blank disk first reports “Unable to boot”, press Enter to reach the menu.

At the Indy PROM’s >> prompt:

boot -f scsi(0)cdrom(6)rdisk(0)partition(8)ip2xboot

The 6 matches the CD-ROM’s SCSI ID. If you attached it at ID 4, use cdrom(4) instead. The installer displays Newport’s black-to-green gradient.

Run sysinst

  1. Choose Install NetBSD to hard disk. Confirm that sd0 is your new 6 GiB disk before formatting it, then accept the default partition sizes.
  2. Choose Full installation and CD-ROM / DVD. If prompted for the set directory, enter sgimips/binary/sets. Wait for all 15 sets to unpack.
  3. Set the root password. In the configuration menu, set Enable xdm (X Display Manager) to YES and create your regular login account.
  4. Select Finished configuring, then Exit Install System. At the installer’s # prompt, enter halt and wait for the disk to unmount.

Boot the installed system

Prismatic: in F9 / Media, disconnect the CD at ID 6 and leave the disk at ID 1. Select F9 / General / PROM boot / NetBSD, save, and start the Indy. Choose Start System if the PROM menu appears.

Standalone IRIS: once halt has returned to the PROM, eject the CD with scsi eject 6 in the host monitor. In the guest display, choose 5 — Enter Command Monitor and set the NetBSD boot variables below. Keep the same nvram.bin for future boots; it stores this machine’s PROM settings.

At the Indy PROM’s >> prompt (also usable for a manual Prismatic disk boot):

setenv OSLoader boot
setenv OSLoadFilename netbsd.boot
setenv OSLoadOptions auto
boot

The installed kernel draws the SGI-style frame around the boot messages before xdm starts, even without an IRIX donor. The first boot builds the font cache. Log in at xdm with the account you created; you should reach a 1280×1024 ctwm desktop with a terminal.

This installer includes xiriprep. Continue to donor import to select the IRIX desktop for your account.

Use an existing Indy

If your disk was installed from an earlier native or xiriprep ISO, update the tools and profiles without reinstalling. Boot that disk at SCSI ID 1. Attach .work/images/xiriprep-indy-donor-profiles-tools.iso through Prismatic’s F9 / Media / SCSI ID 6 / CD-ROM or IRIS’s CD picker. Keep the previous tools CD and back up any customized installed tools before updating.

In a root shell inside the XiriBSD guest:

mkdir -p /cdrom
mount -r -t cd9660 /dev/cd0a /cdrom
(cd / && tar -xzpf /cdrom/xiriprep.tgz)
umount /cdrom

Eject the tools CD, then attach your donor media. The current xiribsd-indy-donor-profiles-11.99.11.iso already includes these tools and all five profiles.

Revert the tools update

If you previously used xiriprep-indy-desktop-tools.iso, reattach that CD and repeat the mount and extraction above. Restore customized tools from your backup. Follow the rollback instructions and hash checks to remove the three added profiles only when they still match their shipped contents.

This tools update and rollback preserved the existing 4Dwm account and preferences on both original reference releases. Kernel, module, and desktop runtime upgrades have separate recovery procedures.

Import your IRIX desktop

Run /usr/local/sbin/xiriprep as root inside XiriBSD. Supply the path to an image file on a mounted filesystem. In the examples, replace xiritest with the ordinary NetBSD login you want to prepare.

Use a complete donor export. If the IRIX installation lives in an emulator overlay, stop the emulator and export the merged disk first. A large raw base file can still contain an empty SGI volume header. See the donor export and profile guide.

Option A: CHD on a data CD

Create a data ISO with your standalone donor CHD. Choose a new output filename and replace the path after the equals sign. The file inside the CD will be named IRIX donor.chd. The 5.3 GiB SuperIRIX CHD exceeds this command’s single-file limit; use the second-disk method below for that image.

On your workstation:

genisoimage -R -V OWNER_DONOR -o irix-donor.iso -graft-points \
  'IRIX donor.chd=/absolute/path/to/standalone.chd'

Attach irix-donor.iso to the CD-ROM at SCSI ID 6, using Prismatic’s F9 / Media or IRIS’s CD picker.

In the guest root shell:

mkdir -p /cdrom
mount -r -t cd9660 /dev/cd0a /cdrom
/usr/local/sbin/xiriprep --check --source '/cdrom/IRIX donor.chd' --user xiritest
/usr/local/sbin/xiriprep --source '/cdrom/IRIX donor.chd' --user xiritest

The optional --check identifies the release, reports the selected desktop profile and account status, and checks any existing installation receipt. It does not change the donor, account, or session. The command without --check verifies every file in the selected plan before publishing the shared desktop. Once it reports that the desktop is selected, run umount /cdrom and eject the CD.

Option B: CHD or raw image on a second disk

The tested setup used a second disk at SCSI ID 2, with an FFS filesystem on /dev/sd1c containing the exported IRIX disk as a regular file. Use the device and filename that match your disk.

In standalone IRIS, halt the guest and stop the emulator before adding this entry to iris.toml, then restart. Its path names the FFS carrier disk containing the donor file.

[[devices]]
type = "hdd"
at = "scsi0/t2"
path = "/absolute/path/to/donor-carrier.raw"
overlay = false

In the guest root shell:

mkdir -p /mnt/donors
mount -r -t ffs /dev/sd1c /mnt/donors
/usr/local/sbin/xiriprep --check --source '/mnt/donors/IRIX backup.img' --user xiritest
/usr/local/sbin/xiriprep --source '/mnt/donors/IRIX backup.img' --user xiritest

After a successful import, run umount /mnt/donors. The reader detects the format by content: either medium can contain a CHD or a raw whole-disk image, subject to the medium’s file-size limit. It reads the mounted file directly, including compressed CHD data.

Use the SuperIRIX 6.5.22m donor

Extract the operating-system disk irix65.chd from irix65_chd.rar. The separate Freeware CHD supplies optional package media. See the archive checksums and provenance for the tested donor.

The operating-system CHD is 5.3 GiB, so put it on an FFS carrier disk. The following example uses NetBSD’s nbmakefs from the local cross-build tools; adjust its location and the extracted CHD path for your workstation. Use a new work directory and output file. This copies the standalone base image; export a stopped donor’s merged disk first if you want changes from an emulator overlay.

On a Linux workstation, from the Xiri checkout:

mkdir .work/superirix-media
cp --reflink=auto "$HOME/Downloads/irix65_chd/irix65.chd" .work/superirix-media/
.work/netbsd-irix-build/tools/bin/nbmakefs -t ffs -B be -o version=2 \
  .work/superirix-donor.ffs .work/superirix-media

Halt the guest and stop the emulator, then attach .work/superirix-donor.ffs as a hard disk at SCSI ID 2. In standalone IRIS, use this file’s absolute path in the scsi0/t2 entry above. Restart XiriBSD from the system disk at ID 1.

In the guest root shell, with the carrier disk identified as sd1:

mkdir -p /mnt/donors
mount -r -t ffs /dev/sd1c /mnt/donors
/usr/local/sbin/xiriprep --check --source /mnt/donors/irix65.chd --user xiritest
/usr/local/sbin/xiriprep --source /mnt/donors/irix65.chd --user xiritest

Look for Identified IRIX 6.5.22m and Desktop profile: 6.5.22m.plan. After a successful import, run umount /mnt/donors. The desktop import selects its planned components; it does not copy every application or the donor user’s home directory.

Reboot and log in

The first import installs the shared desktop and fonts and prepares the native services. Remove the donor media and reboot before the selected account’s first 4Dwm login.

In the guest root shell:

shutdown -r now

Boot from the installed system disk and log in at xdm with the selected account’s usual credentials. The tested Indy installations with 6.5.22f, 6.5.22m, and 6.5.30f donors reach 4Dwm at 1280×1024 with Toolchest, Icon Catalog, winterm, and xclock.

To check the Screen Saver, open its control panel, select Qix, and click Demo. Press Space to return. A user who kept the default XiriBSD session still gets ctwm.

See the original reference-donor results and the additional donor results and screenshots. The new checks cover persistent Qix settings and a separate native ctwm login. Optional xmahjongg installation and removal were also tested with the Indigo2 6.5.22f and Octane 6.5.30f donors; the SuperIRIX 6.5.22m test covers the desktop.

Accounts and storage

  • Existing account: its native home and password are preserved. A previous ~/.xsession is saved as ~/.xsession.before-xiriprep; repeating the command preserves that backup. Restore it to return to the previous session. Other logins keep their current desktops.
  • Missing account: after identifying the donor, xiriprep offers to create the user. The default is No. If you choose Yes, it creates an ordinary user with home /usr/people/<login> and prompts for a password. Create the account beforehand for non-interactive use.
  • Another user: repeat xiriprep with the intended login. A matching shared installation is reused.
  • Another IRIX release: use a separate system disk. Keep 6.5.22f, 6.5.22m, and 6.5.30f separate. The tools reject a donor release that conflicts with an existing desktop receipt.

The reader identifies the release and desktop profile from the combined fingerprints of the donor’s shell, 4Dwm, and Toolchest. The shell and 4Dwm alone are identical on the tested 6.5.22f and 6.5.22m disks. It then verifies the required executables, libraries, fonts, resources, and catalog links in private staging directories before publishing the desktop. Allow the following free space:

Filesystem containingFree space
/var/db192 MiB
/emul184 MiB
/usr/local/share/xiri8 MiB

The shared desktop lives at /emul/irix and its fonts at /usr/local/share/xiri/fonts. On a typical single-filesystem Indy install, the staging tree is renamed into place. If verification fails, correct the donor or free the requested space and rerun.

Browser, freeware, and audio packages have separate installation instructions. The five profiles cover the tested donors’ desktop resources. Newly encountered library or optional-component combinations need their own audit and, where necessary, another import profile.

Build the media

Developers can build the native ISO from the Xiri checkout on a Linux workstation. The documented requirements include Python 3.11+, Git 2.38+, CMake 3.19+, genisoimage, isoinfo, C and C++ compilers, the NetBSD cross-build prerequisites, and access to the pinned libchdr, FAM, and pkgsrc sources.

On the workstation, from the Xiri checkout:

scripts/build-xiribsd-iso.py --work .work/native-indy \
    --output .work/images/xiribsd-indy-native.iso

The output filename is selectable. When using this example, attach the generated xiribsd-indy-native.iso as the installer CD in the fresh-install steps above.

The builder records its source revisions and recipe hashes in .work/native-indy/sources.json and reuses that lock on retry. Archive it alongside the ISO. To reproduce the current installer with all five profiles, use the five-profile installer lock with the Xiri recipe revision recorded in its xiri field, passing the lock file with --lock. The earlier indy-xiriprep-20261127.json lock reproduces the two-profile installer.

See the full build instructions for source preparation, toolchain reuse, and Toolbox options.

Rebuild the tools CD

On the workstation, from the Xiri checkout:

python3 scripts/package-xiriprep-tools.py installer.iso tools.iso

Use a current installer for installer.iso and a new output path for tools.iso. The installer and tools CD contain native components and release inventories. The original IRIX desktop comes from the owner’s donor. The installed reader’s source archive is /usr/local/share/xiri/xiriprep-source.tgz.
